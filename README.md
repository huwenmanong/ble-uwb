# 基于BLE和UWB的汽车数字钥匙定位方法研究

硕士论文研究代码、实验复核与阶段文档。仓库名称为 `ble-uwb`，本地 Git 工作目录为 `SCI-UWB`；目录名称沿用早期公开数据集研究，不代表当前仍以 SCI 投稿为目标。

## 当前主线（2026-11-05）

最新状态：[研究阶段总结（2026-11-06）](研究阶段总结_2026-11-06.md)。已完成动态BLE隔离修正、车内外算法比较及熵消融；用户决定停止熵路线。后续以图表整理与论文成稿为主，不重开模型或分组搜索。下方2026-11-05入口保留方法细节。

研究以车辆数字钥匙定位为背景，组织为 BLE 定位与运动趋势分析、UWB 物理信息辅助定位及结果平滑两部分。BLE 与 UWB 来自不同采集平台、没有同步联合观测，当前不能声称已经实现或验证端到端 BLE/UWB 融合定位。

### 当前 UWB 核心结果

原固定来源分组，外层五折、内层按来源划分，三个训练种子；表中为各运行指标的三种子平均，单位 cm，非坐标集成结果。

|机制|未滤波平均误差|固定滤波后平均误差|未滤波P90|固定滤波后P90|
|---|---:|---:|---:|---:|
|完整 gated|40.90|37.39|75.69|70.07|
|恒等锚点权重|41.10|37.91|72.66|66.89|
|仅直接回归输出|55.07|54.47|95.89|101.02|

当前较有支持的机制是直接坐标回归与 WLS 残差校正输出的融合。质量门控独立收益小且不稳定，不能作为显著精度提升的核心解释。新分组下完整方案并非稳定优于 RBF；历史 PPT 的 25.88 cm 为开发选参结果，不能替代当前分组验证结果。以上均不构成跨车辆泛化或独立盲测结论。

## 环境与复现边界

本机使用 PyCharm 配置好的 Python 3.9 `bluekey` 环境，解释器 `D:\anaconda\envs\bluekey\python.exe`。机制消融运行配置名为 `UWB PPT Mechanisms`，脚本已有输出目录时会停止，避免覆盖历史结果；请勿把重复运行当作查看结果的必要步骤。

部分脚本导入本地上一级目录的历史 UWB 模块，并读取本地配置、车辆数据及中间文件。这些依赖未全部打包进仓库，因此**本仓库尚不是克隆后即可独立运行的软件包**。历史运行说明见 [脚本运行说明](04_算法实现/脚本运行说明_bluekey.md)。

## 版本与数据管理

`main` 用于整理后的论文研究主线，`research/sci-uwb-20261030` 保留研究过程。文档按日期记录：旧文档中的“下一步”代表当时计划，以最新阶段整理为准。
